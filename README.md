# Atoms Demo — 让想法成为可用的应用

用 Python + FastAPI + SQLite 实现的单页应用工作台。可以直接使用实用模板、编辑 HTML、管理版本和项目；接入 DeepSeek 后，还可以通过对话生成、修改 HTML/CSS/JavaScript 应用，并在隔离预览里操作。

## 当前状态

- 首页、模板库、我的项目，以及对话和预览并排的编辑工作台。
- 三个无需 API 的可用模板：**今日清单、生活账本、一刻专注**。模板带实际交互、数据保存和错误提示，创建时明确标注来源。
- 项目搜索与排序、重命名、复制、归档及恢复；桌面/手机预览、HTML 编辑与导出、版本历史、JSON 备份与导入。
- DeepSeek 接口代码已接入；**真实模型调用尚未验证**。离线模式的界面关闭 AI 自由生成入口，使用模板或手动编辑代码；后端保留固定示例适配器供流程测试。
- **目前仅本机运行，尚未部署公网，也未提交 GitHub。** Docker 配置已提供，目标部署环境仍需验证。

界面参考提供的 Atoms 截图：浅灰侧栏、大面积留白、白色圆角卡片、蓝色强调，以及左侧对话/右侧预览的布局。会员积分、支付和云发布不在当前功能范围内。

## 本地启动

需要 Python 3.11+。在项目目录打开终端：

```bash
LLM_MODE=mock bash run.sh
```

打开 <http://127.0.0.1:8765>。首次启动会创建虚拟环境、安装依赖，并在 `.env` 不存在时从 `.env.example` 创建配置；已有配置不会被覆盖。安装依赖需要联网，安装后使用三个模板无需模型 API。

终端按 `Ctrl+C` 停止。端口被占用时：

```bash
LLM_MODE=mock PORT=8766 bash run.sh
```

随后打开 <http://127.0.0.1:8766>。

### 启用真实模型

在本机 `.env` 中填写 `DEEPSEEK_API_KEY`，确认 `DEEPSEEK_MODEL` 是账户可用的模型。如果编辑器没有保存隐藏文件，也可以在项目终端运行 `python3 scripts/configure_key.py`，按隐藏输入的提示填写。不要将密钥发到聊天或提交 Git。停止旧服务后启动：

```bash
LLM_MODE=deepseek bash run.sh
```

后端需要能访问 DeepSeek；浏览器不接触密钥。修改配置后需要重启，显式设置的环境变量优先于 `.env`。模型配置成功仅表示发现了密钥，不等于完成真实调用验证。

## 怎么使用

1. **从模板开始**：在首页或模板库选择应用，创建自己的项目。今日清单支持添加事项、截止日期、完成状态和筛选；生活账本支持支出分类、月度统计和删除；一刻专注支持自定义时长、暂停继续和完成记录。
2. **操作并保存**：模板里的待办、支出和计时状态会自动保存。刷新预览后恢复。番茄钟按结束时间恢复计时，每次只结算当前阶段，下一阶段由用户手动开始。
3. **修改应用**：进入代码视图，编辑完整 HTML 并保存为新版本。已配置真实模型时，也可以在对话区提出新需求，查看计划、生成、检查和必要时的一次修复进度。
4. **管理版本**：查看历史版本并恢复代码。恢复不会删除后续版本，也不会回退业务数据。若另一页面已修改当前代码，保存会拒绝覆盖旧版本，需要重新加载最新代码。
5. **管理项目**：在“我的项目”搜索、排序、重命名、复制或归档。归档后先恢复再编辑。复制会创建独立项目，复制代码、版本和业务数据。
6. **备份或分享成果**：导出 HTML 得到可独立运行的页面；导出 JSON 备份可保留项目代码、历史版本和业务数据，导入后创建一个新项目。

### 两种导出的区别

| 方式 | 包含内容 | 适用场景 |
| --- | --- | --- |
| HTML | 当前代码及独立页面存储适配器；不含服务器已有业务数据 | 展示/使用生成的单页应用 |
| JSON 备份 | 项目名称、代码、当前版本、全部版本与业务数据 | 迁移到另一浏览器或恢复备份 |

JSON 备份不包含完整对话记录、登录会话、API Key 或环境配置。最多支持 100 个版本、20MB 文件；每个项目业务数据最多 20KB。模板会在接近数据容量时提示清理。

## 保存、会话与运行边界

项目、对话、版本与业务数据保存在 SQLite。应用内部使用工作台注入的数据接口：

```javascript
const data = await window.demoStorage.load();
await window.demoStorage.save({ tasks: [] });
```

预览在隔离 iframe 内运行，通过校验消息来源的桥接读写当前项目的数据。应用只能使用自包含 HTML/CSS/原生 JavaScript；不支持 npm 构建、生成后端、外部脚本、网络请求或第三方 API。

浏览器通过随机 HttpOnly Cookie 区分会话，项目接口验证归属。**当前没有账户登录和跨设备同步**；清除 Cookie、Cookie 过期或切换浏览器后不会自动找回原项目。需要迁移时，提前导出 JSON，再在目标浏览器导入。HTML 独立导出页的数据仅保存在该页使用的浏览器中。

HTML 检查只检查结构、代码大小和部分受限依赖，不等于完整功能或安全测试。手动保存与生成失败均保留上一版本。服务使用一个 Uvicorn worker、一个实例；SQLite 版本不支持横向扩容。

## 配置

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `LLM_MODE` | `deepseek` | `mock` 用于离线模板体验和测试；`deepseek` 使用真实模型 |
| `DEEPSEEK_API_KEY` | 空 | 仅在本地 `.env` 或服务器环境变量填写 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 模型接口地址 |
| `DEEPSEEK_MODEL` | `deepseek-flash` | 当前代码的默认配置，按账户实际可用模型调整 |
| `DATABASE_PATH` | `./data/demo.db` | 相对项目目录；上线时指向持久磁盘 |
| `MODEL_TIMEOUT_SECONDS` | `120` | 单次模型调用总时限 |
| `MAX_RUNS_PER_OWNER_PER_DAY` | `20` | 每个浏览器会话每天的生成尝试上限 |
| `MAX_RUNS_GLOBAL_PER_DAY` | `100` | 全站每天的生成尝试上限 |
| `COOKIE_SECURE` | `false` | HTTPS 部署时改为 `true` |

一次生成通常调用两次模型，结构检查失败时最多增加一次修复调用。配额按 UTC 日期和尝试次数计算，失败也占用一次；停止本地请求不保证撤销上游已产生的费用。

## 项目结构与验证

| 文件 | 作用 |
| --- | --- |
| `app/main.py` | API、会话归属校验、生成进度、备份与导出 |
| `app/db.py` | SQLite、项目管理、版本与冲突检查 |
| `app/agent.py` / `app/llm.py` | 生成工作流、提示词、DeepSeek 调用与错误处理 |
| `app/templates.py` / `app/templates/` | 三个实用应用模板及目录 |
| `app/static/` | 工作台界面、预览、数据桥接 |
| `app/mock.py` / `app/example.html` | 固定示例模型，供离线流程测试 |
| `tests/` | HTTP 流程、模型适配器及异常场景测试 |
| `Dockerfile` | 单实例容器部署配置 |

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
node --test tests/preview_bridge.test.mjs
node tests/template_behavior.test.mjs
```

自动化测试不使用真实密钥、不产生 API 费用。新版页面的脚本流程已用独立数据库做集成检查；完整浏览器的视觉与点击验收仍需按 [VALIDATION.md](VALIDATION.md) 的清单完成。真实模型仍需验证不同需求生成、连续修改、预览操作、刷新恢复和版本回退。

## 公网部署与提交

按步骤操作请看 [DEPLOY.md](DEPLOY.md)：本机接入 DeepSeek、上传 GitHub，以及使用 Render 发布完整工作台。

使用支持 Python 的服务器或容器托管平台，并为 SQLite 配置持久磁盘。只上传静态前端无法提供模型接口和后端保存能力。示例容器命令：

```bash
docker build -t atoms-demo .
docker volume create atoms-demo-data
docker run --rm -p 8000:8000 --env-file .env \
  -e DATABASE_PATH=/data/demo.db \
  -v atoms-demo-data:/data atoms-demo
```

目标环境需要验证镜像构建、HTTPS、环境变量、持久数据和 SSE。HTTPS 时设置 `COOKIE_SECURE=true`；保留一个 worker，反向代理关闭 SSE 缓冲并允许足够长的连接。容器默认端口为 8000。

最终提交包括：可访问的 Demo 地址、GitHub 源码地址、运行说明与真实模型验收结果。提交前排除 `.env`、数据库、虚拟环境与个人业务备份。推荐演示“创建应用→操作预览→继续修改→刷新恢复→版本回退”。
